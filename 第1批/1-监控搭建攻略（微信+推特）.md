# 信息监控攻略 · 完整搭建与运维手册

> 整理日期：2026-09-17
> 适用：Windows + 本地电脑常开 + 推送到手机

---

## 〇、这套东西是干什么的

让机器替你守着两个信息源，**不错过重要的东西**：

```
微信（本地数据库）  →  群话题 / 重点人未回  →  企业微信推手机
推特 / X           →  关注的博主新推文      →  企业微信推手机
```

**核心原则**：

```
1. 数据不出门（微信数据只在本机解密分析）
2. 手机不用开梯子（抓取在电脑，手机只负责收）
3. 不买云服务器（用计划任务 + 本地进程替代）
```

## 一、微信监控

### 1.1 原理

```
微信把聊天记录加密存在本地 SQLite
      ↓
用内存里读出的密钥解密
      ↓
读消息 → AI 归纳 → 推送
```

### 1.2 关键文件（都在 `.\微信监控\`）

```
脚本\wechat_monitor.py     主程序（扫描循环 + 汇总 + 提醒）
脚本\wechat_reader.py      读库模块（解密 + 查询）
脚本\ai_helper.py          AI 调用（分级 + 失败升级）
脚本\push.py               推送模块（在 quant 探索\脚本\）
脚本\topic_lookup.py       按编号捞话题原文
脚本\all_keys.json         数据库密钥
微信监控配置.json           全部配置
数据\monitor.log           运行日志
数据\话题存档.json          话题存档（保留 72 小时）
数据\微信消息流水.csv       消息流水
```

### 1.3 它做的四件事

| 功能 | 说明 |
|---|---|
| 群消息扫描 | 全部 142 个群，按忽略清单跳过 9 个 |
| 每小时话题汇总 | AI 归纳成话题目录，只推目录不推原文 |
| 话题追问 | 回复编号（如 T3）可捞该话题的原文 |
| 重点人未回提醒 | 重点人发消息 5 分钟没回 → 企业微信 @所有人 |

### 1.4 重点人提醒的三个约束

```
按波切分    session_gap_hours = 6    老消息不拖累新消息
超时上限    max_wait_hours = 12      几个月前的老消息不诈尸
静默期      quiet_minutes = 30       提醒过一次 30 分钟内不重复
```

### 1.5 启动方式

```
计划任务 XiaoHuaWeChatMonitor       每 15 分钟检查进程，不在就拉起
计划任务 XiaoHuaWeChatMonitorBoot   开机自动启动
启动脚本 启动监控.bat（后台 pythonw + 日志）
```

### 1.6 配置要点（`微信监控配置.json`）

```json
{
  "push_mode": "both",
  "interval_sec": 300,
  "my_wxid": "wxid_YOUR_ACCOUNT",
  "private_alert": {
    "enabled": true,
    "minutes": 5,
    "quiet_minutes": 30,
    "max_wait_hours": 12,
    "session_gap_hours": 6
  },
  "ai": {
    "task_tier": {"summary": "fast", "topic": "fast"},
    "allow_escalate": true
  },
  "hourly_minutes": 60
}
```

## 二、推特 / X 监控

### 2.1 原理

```
电脑（有梯子 / 或直连）
      ↓ 每 10 分钟
调 twitterapi.io 的搜索接口
      ↓
挑出没见过的推文 → 推送到手机
```

### 2.2 关键文件（`.\X监控\`）

```
monitor_twitter.py        主程序
x_fetch.py                抓取模块（last_tweets / search_new）
推特监控配置.json          配置（名单、频率、API key）
推特监控-最新版.bat        一键启动器（自动提权 + 装计划任务）
status_x.py               查看状态和余额
数据\monitor_x.log        运行日志
数据\已见推文.json         去重库
数据\上次检查时间.json      每人的上次检查时间
```

### 2.3 为什么用 twitterapi.io

```
Nitter          2026-09-15 被 X 告死，免费路断
官方 X API      $200/月，个人不用考虑
twitterapi.io   $0.15/1000 条，按量付费，注册送 $0.1
Stream 实时流   $5/账户/月起，比按条还贵，放弃
```

### 2.4 最关键的省钱改造：搜索模式

**原来（last_tweets）**：

```
每次调用固定返回 20 条 = 扣 300 credits
不管你只要几条，都按 20 条收
试过 count / pageSize / limit / size / num / maxResults / per_page 全部无效
```

**现在（advanced_search）**：

```
查询：from:用户名 since:上次检查时间
返回 0 条  → 扣最低 15 credits
返回 3 条  → 扣 45 credits

成本：从 ¥560/月 降到 ¥28/月（差 19 倍）
```

**但要注意**：

```
每次调用最低 15 credits，不管有没有新推
所以频率越高，这个"底噪"越高
```

### 2.5 成本对照表

```
方案              每天credits    每月约
──────────────────────────────────────
6人 · 每10分钟       12,960      28 元
6人 · 每30分钟        4,320       9 元
6人 · 每1小时         2,160       5 元
6人 · 每2小时         1,080       2 元
2人 · 每10分钟        4,320       9 元
```

### 2.6 启动方式

```
计划任务 XiaoHuaTwitterMonitor      每 15 分钟检查
计划任务 XiaoHuaTwitterMonitorBoot   开机自启
启动器   推特监控-最新版.bat（右键 → 以管理员身份运行）
```

## 三、推送通道

### 3.1 企业微信群机器人（主通道）

```
webhook 在「quant 探索\配置\推送配置.json」的 wecom 字段
普通消息   markdown 格式
紧急消息   text + @所有人（用来提醒重点人未回）
```

### 3.2 ntfy（备用）

```
topic: your-ntfy-topic
服务器: ntfy.sh（境内需梯子）
```

### 3.3 注意

```
· 企业微信 markdown 正文上限 4096 字符 → 推送模块有 3200 字符限长
· 调用企业微信接口时必须绕开代理（否则报 60020）
· 调试时 push.py 有 errcode 检查，不会假成功
```

## 四、踩过的坑（重要）

| # | 现象 | 根因 | 解决 |
|---|---|---|---|
| 1 | 十小时不推汇总 | AI 接口走系统代理被掐断 | 改成直连（`ProxyHandler({})`） |
| 2 | AI 挂了整小时静默 | 失败直接跳过 | 改成失败也推一条说明 |
| 3 | 监控反复停止 | 电脑重启 + 无自启 | 装计划任务（开机自启 + 15 分钟守护） |
| 4 | 同时跑多个监控进程 | 单实例锁的 socket 是局部变量，函数返回被回收 | 改成全局变量持有，并做持久性测试 |
| 5 | bat 中文全乱码 | bat 写成了 UTF-8，cmd 按 GBK 读 | 用 Python 生成 GBK 编码的 bat |
| 6 | 计划任务参数没更新 | 任务里存的是旧的 `--loop 120` | 参数改成 `--loop`（不带数字），读配置 |
| 7 | 推送被企业微信拒 | 正文超过 4096 字符 | 加限长，超出部分标注"还有 N 条" |
| 8 | 查进程误报"没在跑" | 沙箱里读不到进程命令行 | 改成按进程名判断 |
| 9 | API 参数控制不了返回条数 | 接口不支持 | 换接口（搜索模式） |
| 10 | 后台任务每月烧 415 元 | 每 5 分钟跑 pro 模型，且无事可做 | 停用 |

## 五、日常运维

### 5.1 检查监控是否活着

```powershell
# 看进程
Get-Process -Name pythonw

# 看计划任务
schtasks /query /tn "XiaoHuaWeChatMonitor"
schtasks /query /tn "XiaoHuaTwitterMonitor"
```

### 5.2 看日志

```
微信监控：微信监控\数据\monitor.log
推特监控：X监控\数据\monitor_x.log
```

### 5.3 推特余额

```powershell
cd ".\X监控"
python status_x.py
```

### 5.4 改推特监控频率

**改这里**（不用动 bat）：

```
X监控\推特监控配置.json → interval_min
然后双击一次「推特监控-最新版.bat」让它重启
```

## 六、这套东西的边界

```
✓ 微信：只能读本地库，需要微信开着、电脑开着
✓ 推特：需要电脑开着、需要 twitterapi.io 账号有余额
✗ 不能替你回复消息
✗ 不能绕过登录（需要登录的网站，得你本人操作）
✗ 手机端要正常接收，需要企业微信通知权限打开
```
