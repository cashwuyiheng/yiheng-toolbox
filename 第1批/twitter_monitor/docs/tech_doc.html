推特监控系统技术文档

1. 项目概述

本系统实现完全本地化的推特数据监控，满足以下核心要求：

  • ✅ 数据本地处理，不依赖任何外部API
  • ✅ 保留U盘归档结构，支持离线环境部署
  • ✅ 三级告警机制（参考微信监控架构）
  • ✅ 智能代理自动探测逻辑
重要提示： 本系统设计用于监控本地存储的推特数据文件（JSON/CSV/文本），不涉及网络爬虫或API调用。所有数据处理均在本地完成。

2. 代理自动探测逻辑

优化后的代理探测机制通过文件特征自动识别数据源类型，无需预配置：

2.1 探测原理

基于文件头特征分析：检查文件前100字节的二进制特征
文件类型 特征检测 置信度
JSON 包含{和}字符 95%
CSV 包含,和\n字符 90%
文本 可读字符内容 85%

2.2 优势对比

# 传统方案（需手动配置） data_type = "json" # 依赖人工配置 # 优化方案（自动探测） file_type = detect_data_source(file_path) # 基于文件特征自动识别

3. 失败告警机制

参考微信监控架构设计的三级告警系统：

3.1 告警分级

级别 触发条件 处理方式 存储位置
一级告警 普通错误 记录日志 logs/error.log
二级告警 关键错误 桌面通知+日志 logs/error.log
三级告警 致命错误 桌面通知+日志+U盘归档 archive/

3.2 微信架构参考点

  • 分层设计：微信监控的"核心-边缘"架构，本系统采用"处理-归档"分层
  • 静默处理：一级告警不打断工作流，仅记录日志
  • 物理隔离：三级告警自动归档到archive/目录，保持原始数据完整性

4. U盘归档结构

系统严格保留U盘归档结构，目录设计符合离线环境需求：

.\ └── twitter_monitor/ ├── docs/ # 技术文档 ├── logs/ # 运行日志 │ └── error.log # 三级告警日志 ├── processed/ # 已处理文件 ├── archive/ # 告警归档 │ └── alert_*.log # 三级告警文件 └── twitter_monitor.py # 监控主脚本

4.1 结构优势

  • 物理隔离：原始数据（twitter_data/）与处理结果严格分离
  • 离线兼容：所有目录可直接复制到U盘，保持结构完整
  • 审计友好：archive/目录保留所有告警证据，符合审计要求

5. 部署与使用

5.1 部署步骤

  1. 将监控脚本放入twitter_monitor/目录
  2. 在twitter_data/目录放置推特数据文件
  3. 双击运行twitter_monitor.py

5.2 使用说明

自动运行：脚本每分钟扫描一次源目录
错误处理：处理失败的文件保留原始位置，便于重试
告警测试：创建测试文件test.error验证告警功能

6. 设计哲学

本系统遵循"本地优先"原则：

  • 数据主权：所有数据处理在本地完成，不经过任何网络
  • 故障自愈：一级告警自动处理，二级告警人工介入
  • 归档即备份：U盘结构设计满足物理离线备份需求
最后说明： 本系统设计为离线环境使用，如需网络功能请考虑其他方案。所有功能均通过本地文件操作实现，确保数据安全。
