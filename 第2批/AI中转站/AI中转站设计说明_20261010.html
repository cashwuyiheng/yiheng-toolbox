AI 中转站 · 设计说明

日期：2026-10-10　｜　位置：.\AI中转站\　｜　纯标准库，零依赖

一、它是什么

在本机起一个 OpenAI 风格的网关（默认 http://127.0.0.1:8788/v1）。你的聊天客户端、脚本、编辑器插件都指向它，由它决定这条请求去哪家上游模型。

解决三个实际问题：

  1. 换模型不用改客户端。客户端永远写 127.0.0.1:8788，后台换谁由这里决定。
  2. key 集中管理。上游 key 只存在这一个本地文件里，客户端不碰。
  3. 数据可控。中转站自身不落你的 prompt（日志只记「路由到谁」）。

二、架构

客户端(聊天/脚本/IDE)
        │  OpenAI 格式请求，base_url = 127.0.0.1:8788/v1
        ▼
┌──────────────────────────────┐
│  ai_relay.py（本机，127.0.0.1）│
│  ① 鉴权(可选 relay_token)      │
│  ② 路由：显式名 / 上游名/模型 / │
│          关键字 / 默认          │
│  ③ 转发 + 流式透传             │
└──────────────────────────────┘
        │  只转发到你自己配置的上游
   ┌────┴─────┬─────────┐
   ▼          ▼         ▼
 qwen      deepseek   其他兼容 OpenAI 的端点

三、快速开始

# 1. 填配置
copy config.example.json config.json
#    编辑 config.json：填每个上游的 base_url、api_key、model

# 2. 启动
python ai_relay.py

# 3. 客户端 base_url 指向
http://127.0.0.1:8788/v1

看活着没：打开 http://127.0.0.1:8788/healthz，或 GET /v1/models 列上游。

四、配置说明（config.json）

键含义
listen_host / listen_port监听地址与端口，默认 127.0.0.1:8788（只对本机开放）
relay_token本地鉴权口令；填了之后客户端要带 Authorization: Bearer <口令>。留空则不校验
default_upstream兜底走哪个上游
log_path日志文件；留空则只打印不落盘
upstreams[]上游列表：name / base_url / api_key / model / timeout / proxy
upstreams[].proxy该上游单独走代理，如 http://127.0.0.1:7897；留空走直连
routes[]路由规则：match.keywords（命中最后一条 user 消息）或 match.model_prefix

五、路由规则

按顺序判断，命中即用：

  1. 客户端 model 写成 上游名/真实模型 → 用该上游，并覆盖模型名。
  2. 客户端 model 写成 上游名 → 用该上游。
  3. model 为 auto 或空 → 按 routes 关键字 / 前缀匹配，命中就用规则里的上游。
  4. 都没命中 → default_upstream，再退到第一个上游。

六、安全边界

  • 只听 127.0.0.1，不对外网开放；同机程序才能访问。
  • 不改写你的数据，转发后即走即弃，不缓存对话。
  • 日志不记内容，只记「时间 + 路由到哪个上游 + 模型 + 是否流式」。
  • proxy 按上游单独开，避免给国内端点白白套梯子。
  • 想再紧一层：填 relay_token，客户端带口令才放行。
